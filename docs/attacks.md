# Attack demonstrations

Run `pnpm attacks` to regenerate `docs/results/attacks.json`; run `pnpm test` to assert each weak example succeeds and the defense blocks it. All deliberately vulnerable code is labeled `INSECURE-DEMO` in `packages/adversary-sim`. The live Attack Lab runs the same functions in the browser. The server never imports the package.

| ID  | Weak example and observed exploit                                                   | Defense and observed result                                                                                                                                                          |
| --- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A1  | `SHA-256(move)` reveals one of three moves by enumeration.                          | A random 32-byte salt makes three guesses with an unknown salt fail; Pedersen is perfectly hiding for uniform `r`.                                                                   |
| A2  | A known linear-congruential seed predicts `r`, allowing enumeration of the move.    | The browser's cryptographic RNG produces an unpredicted scalar; the guessed `r` does not open the commitment.                                                                        |
| A3  | Choosing `h = 7g` lets the maker calculate a second `(move, r)` for the same point. | The pinned hash-to-curve `h` rejects that forged opening. Unknown discrete log is an assumption, not something an experiment proves.                                                 |
| A4  | A referee that trusts the final move lets a player switch from rock to paper.       | Pedersen verification rejects the changed move. The API records invalid openings and forfeits.                                                                                       |
| A5  | A referee without a duplicate check accepts an opponent's point.                    | The API rejects duplicate points across a match; signed payloads differ by player and round.                                                                                         |
| A6  | An early-exit comparator inspects 1 versus 64 characters for different prefixes.    | Fixed-work comparison inspects 64 in both cases; the server uses Node `timingSafeEqual` for fixed-length secret comparisons. Counts show branch behavior, not remote exploitability. |
| A7  | Length-only validation accepts a 33-byte invalid point encoding.                    | Strict compressed P-256 parsing rejects invalid or noncanonical points.                                                                                                              |
| A8  | A referee without deadlines accepts a late reveal.                                  | The referee rejects actions after its deadline and resolves forfeits; API tests cover missed commit and reveal deadlines.                                                            |
| A9  | A signature over `C` alone verifies again in another round.                         | A signature over tournament, match, round, player, mode, and `C` fails if the round changes.                                                                                         |
| A10 | A plain event log displays an altered winner.                                       | The browser hash-chain verifier detects a modified row. A complete server rewrite remains possible without an external checkpoint.                                                   |

The A6 live demo is structural. A separate [local timing study](benchmarks.md#comparison-timing-study) found a clear early-exit difference (Welch p ≈ 3.1×10⁻²⁴⁰) and no detectable difference for Node `timingSafeEqual` (p ≈ 0.605) in this run. These measurements cannot prove a whole HTTP path constant-time. For A8, deadlines are server-controlled; a malicious server can still manipulate its own clock or resolve unfairly.
